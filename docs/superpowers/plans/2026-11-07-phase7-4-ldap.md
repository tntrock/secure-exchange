# Phase 7.4 — LDAP/AD Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Staff can sign in with their AD/LDAP domain account. The account is created on first login, its role follows an admin group, and an existing session is re-checked against the directory every 15 minutes. The check fails closed: if the directory cannot be reached, the session ends.

**Architecture:**
- A new `internal/ldapauth` package talks to the directory through a narrow `conn` interface, so tests use a fake instead of a real server.
- External accounts are keyed by `(auth_source, external_id)`; email uniqueness becomes per source.
- `requireRole` claims a per-session check every 15 minutes and calls `Directory.Lookup`.
- The login page gets a second form when LDAP is enabled.

**Tech Stack:** Go 1.26, pgx/v5, goose, `github.com/go-ldap/ldap/v3` (MIT, new dependency); React 19 + TS, vitest, react-i18next.

**Spec:** `docs/superpowers/specs/2026-11-07-phase7-admin-design.md` (§4.1, §4.2, §4.4 last-admin note, §8 item 4, §9 "現有資料" bullet and session-invalidation bullet). Parent: `docs/superpowers/specs/2026-10-24-secure-exchange-design.md` §5.10.

- Spec §4.1:

  - **Directory unreachable during a re-check → end the session.** Local admins are unaffected.
  - No TOTP for LDAP accounts.
- The last-local-admin guard (7.2) is unchanged; external admins do not count.
- Role change and TOTP reset stay refused for external accounts (7.2 `ErrExternal`).

## Rulings made while planning (my calls)

- **Env vars:**
  - `SX_LDAP_URL`: `ldaps://host:636` or `ldap://host:389`. Empty means LDAP is off.
  - `ldap://` **always** uses StartTLS; there is no switch to turn it off, so a plaintext bind cannot be configured.
  - `SX_LDAP_CA`: PEM path; system roots when empty. Reuse `config.CertPool`.
  - `SX_LDAP_BIND_DN`, `SX_LDAP_BIND_PASSWORD`, `SX_LDAP_BASE_DN`: required when the URL is set.
  - `SX_LDAP_USER_FILTER`: default `(&(objectClass=user)(|(sAMAccountName={username})(userPrincipalName={username})))`. It must contain `{username}`, which is replaced with the escaped input.
  - `SX_LDAP_ID_ATTR` default `objectGUID`, `SX_LDAP_EMAIL_ATTR` default `mail`, `SX_LDAP_NAME_ATTR` default `displayName`.
  - `SX_LDAP_ADMIN_GROUP`: a group DN; empty means nobody becomes admin via LDAP.
- **`external_id`:** lowercase hex of the raw id attribute bytes. This covers binary `objectGUID` and text ids alike.
  - For the re-check, the lookup filter is `(<idattr>=\xx\xx…)`, with every byte escaped as `\%02x`.
- **Email:** the email attribute, falling back to `userPrincipalName`. If both are empty, login fails with stage `ldap_no_email`.
- **Admin check:**
  - The user is admin if the entry's `memberOf` holds the group DN (case-insensitive), **or** if a base-scope search on the user DN with filter `(memberOf:1.2.840.113556.1.4.1941:=<groupDN>)` (AD in-chain, nested) returns the entry.
  - If that search fails with an LDAP result error, such as a server without the matching rule, the result is "not via chain". Connection errors fail the whole operation.
  - Effect: AD gets nested groups; other LDAP servers get direct membership. The manual says so.
- **Disabled:**
  - `userAccountControl` bit `0x2` set means disabled.
  - Login fails with stage `ldap_disabled`; a re-check ends the session.
  - A missing attribute is treated as enabled (non-AD servers).
- **Directory unavailable:**
  - At login: 503 `directory_unavailable`, audited as stage `ldap_unavailable`.
  - At re-check: delete that session, return 401, and audit `auth.session.end` with reason `ldap_unavailable`.
  - If the account is gone or disabled: delete all of that user's sessions, with reason `ldap_gone`.
- **Ambiguous search** (more than one entry) and an empty password are invalid credentials. The empty-password check happens before any network call (unauthenticated bind).
- **Same email, two LDAP accounts:** the second login gets 409 `email_conflict`, audited.
- **Login audit:** `auth.login.ok` / `auth.login.fail` detail carries `source: "ldap"` and `username`. On a role change, `role_from` and `role_to` are added.
- **Timeouts:** every LDAP network operation has a 10 s timeout.
- **Rate limits:** `perIP` plus `accountLimit` key `ldap:<lowercased username>`.
- **Login page:** a "網域帳號" form appears when `GET /api/auth/methods` returns `{ldap: true}`. Task 7.5 will add OIDC fields to the same endpoint.
- **Local admin flagged as LDAP:** an admin-disabled LDAP user (`users.disabled`) cannot log in even with valid AD credentials.

## Review Focus

1. **Empty password.** It must never authenticate, because many directories accept an unauthenticated bind. Pinned by Task 2 `TestAuthenticateEmptyPasswordNoNetwork`.
2. **Filter injection in the username** (`*)(sAMAccountName=*`). The input is escaped and matches nobody else. Pinned by Task 2 `TestAuthenticateEscapesUsername`.
3. **Local account with the same email as an AD user.**
   - The LDAP login creates or uses a separate `ldap` account.
   - The local password login still reaches only the local account.
   - The LDAP login never returns the local account.
   - Pinned by Task 1 `TestByEmailLocalOnly` and Task 3 `TestLDAPLoginNeverTouchesLocal`.
4. **AD unreachable mid-session.** At the next check, more than 15 minutes later, the LDAP session ends and a local admin session keeps working. Pinned by Task 3 `TestRecheckFailsClosed`.
5. **User removed from the admin group.** The next login, or the next re-check, demotes them to staff and admin routes return 403. Pinned by Task 3 `TestRecheckDemotes`.
