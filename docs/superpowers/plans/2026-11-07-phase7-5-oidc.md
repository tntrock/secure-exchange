# Phase 7.5 — OIDC (Entra ID) Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Staff can sign in with an OIDC identity provider (Entra ID first; Google Workspace and Keycloak work with the same settings) through a 「以 Microsoft 登入」 button. The account is created on first login, and its role follows an admin claim at every login. The session ends at `SX_SESSION_TTL`.

**Architecture:**
- A new `internal/oidcauth` package wraps `coreos/go-oidc/v3` and `golang.org/x/oauth2` and runs Authorization Code + PKCE.
- The per-login `state`, `nonce` and PKCE verifier live in one short-lived `HttpOnly` cookie, so there is no new table and several app instances work without shared state.
- httpapi talks to the provider through a narrow interface, so handler tests use a fake. The `oidcauth` tests run against an in-test fake IdP (httptest TLS server: discovery, JWKS, token endpoint).
- External accounts reuse 7.4's `UpsertExternal` with source `oidc`. Migration 0001's CHECK already allows `'oidc'`, so there is **no migration**.

**Tech Stack:** Go 1.26, pgx/v5; new dependencies `github.com/coreos/go-oidc/v3` (Apache-2.0) and `golang.org/x/oauth2` (BSD-3). `github.com/go-jose/go-jose/v4` comes in with go-oidc and is used by the fake-IdP tests. Web: React 19 + TS, vitest, react-i18next.

**Spec:** `docs/superpowers/specs/2026-11-07-phase7-admin-design.md` (§4.1, §4.3, §4.4 last-admin note, §8 item 5, §9 "session 何時失效" and "OIDC 身分欄位"). Parent: `docs/superpowers/specs/2026-10-24-secure-exchange-design.md` §5.10.

## Rulings made while planning (my calls)

- **Env vars** (`config.OIDCConfig`, `Config.OIDC`):
  - `SX_OIDC_ISSUER`: the issuer URL. Empty means OIDC is off. It must be `https://`.
    - For Entra this is `https://login.microsoftonline.com/<tenant-id>/v2.0`. The manual says the tenant-specific URL is required, because `common` and `organizations` do not match the token's `iss`.
  - `SX_OIDC_CLIENT_ID` and `SX_OIDC_CLIENT_SECRET` are required when the issuer is set. Read the secret untrimmed, like `SX_LDAP_BIND_PASSWORD`.
  - `SX_OIDC_SCOPES`: default `openid profile email`, separated by spaces. `openid` is added if it is missing.
  - `SX_OIDC_ADMIN_CLAIM`: default `groups`. `SX_OIDC_ADMIN_VALUE`: empty means nobody becomes admin through OIDC.
  - `SX_OIDC_BUTTON_TEXT`: when empty, the button uses the i18n text 「以 Microsoft 登入」 / "Sign in with Microsoft". When set, it is shown verbatim.
  - `SX_OIDC_CA`: optional root CA for an internal IdP such as Keycloak. Use `config.CertPool` (PEM or DER). When empty, use the system roots.
  - Redirect URI: `SX_BASE_URL` + `/api/auth/oidc/callback`. There is no separate variable; the manual tells the admin to register this exact URI.
- **No network at startup.** `oidcauth.New` validates the config only. Discovery runs on the first login and is cached after it succeeds; a failure is retried at the next login. So an IdP outage never stops the app from starting, and local admins can still log in.
- **Flow cookie `sx_oidc`:**
  - Value `<state>.<nonce>.<verifier>`. Each part is 32 random bytes in base64url (`oauth2.GenerateVerifier()` for the verifier).
  - `HttpOnly; Secure; SameSite=Lax; Path=/api/auth/oidc; Max-Age=600`.
  - It **must be Lax**: the callback is a cross-site top-level GET from the IdP, and a Strict cookie would not be sent.
  - The callback always clears it (Max-Age=-1), on success and on failure.
  - The query `state` must equal the cookie state, compared with `subtle.ConstantTimeCompare`. A missing cookie, a malformed cookie or a mismatch fails with stage `oidc_state`. This blocks login CSRF.
- **Session cookie:** it stays `SameSite=Strict`. The callback sets it and redirects `302` to `/files`. The SPA's later `fetch` calls are same-site, so the cookie is sent.
- **external_id:** `iss + " " + sub`. Issuer URLs contain no spaces.
- **Identity:**
  - Email comes from the first non-empty of `email`, `preferred_username`, `upn`. If all are empty → `ErrNoEmail`.
  - Name is `name`, falling back to the email.
  - Admin is true when the admin value is set and the claim is either a string equal to it or an array with an equal element (exact, case-sensitive: Entra group ids and role names are exact).
  - **Entra groups overage:** if the token has `_claim_names` with a key equal to the admin claim, set `Identity.GroupsOverage = true`. The user becomes staff, and the login audit detail gets `groups_overage: true`. The manual explains that this is why App Roles (`roles`) are recommended.
- **Errors (oidcauth):**
  - `ErrUnavailable`: discovery or JWKS fetch failed, the token endpoint was unreachable or answered 5xx, or the token endpoint rejected the client (`invalid_client`, which usually means an expired client secret). A rejected client is logged at `ERROR` because it is a configuration problem.
  - `ErrInvalid`: the token endpoint answered `invalid_grant` or another 4xx, there is no `id_token`, the ID token fails verification (signature, iss, aud, exp), or the nonce differs.
  - `ErrNoEmail`.
  - Wrap with `fmt.Errorf("%w: %w", …)` as in ldapauth.
- **HTTP timeouts:** one `http.Client{Timeout: 10 * time.Second}` with the CA pool, passed to go-oidc and oauth2 through `oidc.ClientContext`.
- **Callback outcomes:** the callback always ends with a 302. Success goes to `/files`. Failure goes to `/login?oidc_error=<code>`, with this mapping:

  | Situation | `oidc_error` code | Audit `auth.login.fail` stage |
  |---|---|---|
  | The IdP sent `error` (for example the user cancelled) | `denied` | `oidc_denied`, with detail `idp_error` = the IdP's `error` value, truncated to 64 characters |
  | State problem | `invalid` | `oidc_state` |
  | `ErrInvalid` | `invalid` | `oidc_token` |
  | `ErrNoEmail` | `invalid` | `oidc_no_email` |
  | `ErrUnavailable` | `unavailable` | `oidc_unavailable` |
  | Email conflict | `email_conflict` | `email_conflict`, with `external_id` in the detail as in LDAP |
  | Locally disabled account | `invalid` | `disabled` |
  | OIDC is off | — | `GET /api/auth/oidc/start` and the callback return 404 JSON `not_found` |

- **Login audit:** detail carries `source: "oidc"` and `email`. A role change adds `role_from` and `role_to`, as in LDAP.
- **Rate limit:** both endpoints are wrapped in `perIP`. There is no account limit, because no password is guessed here.
- **OIDC turned off after login:** `requireRole` ends an `oidc` session when `s.OIDC == nil`, using the existing `endSession` with reason `oidc_disabled`. This mirrors 7.4's fail-closed rule for LDAP. There is no periodic re-check (spec §4.3); sessions are already absolute (`expires_at`, not sliding), so the `SX_SESSION_TTL` cap needs no new code.
- **Logout:** local logout only. There is no RP-initiated logout at the IdP (YAGNI). The manual says that signing out here does not sign the user out of Microsoft.
- **Methods endpoint:** `GET /api/auth/methods` → `{ldap: bool, oidc: bool, oidc_label: string}`. `oidc_label` is `SX_OIDC_BUTTON_TEXT`, which may be empty.
- **Admin user list:** add `users.sources.ldap` (「網域」 / "Domain") and `users.sources.oidc` (「單一登入」 / "SSO"). 7.4 left `ldap` falling back to the raw value.

## Review Focus

1. **Login CSRF / state mismatch.** A callback whose `state` differs from the cookie, or that arrives with no cookie, must not log anyone in, even with a valid code. Pinned by Task 2 `TestOIDCCallbackStateMismatch`.
2. **A token not meant for us** (wrong `aud`, wrong `iss`, bad signature, expired, or a replayed nonce) is refused. Pinned by Task 1 `TestExchangeRejects` (table).
3. **Same email as a local or LDAP account.** The OIDC login creates a separate `oidc` account, and the local password login still reaches the local account. Pinned by Task 2 `TestOIDCLoginNeverTouchesLocal`.
4. **IdP unreachable.** The app starts, local login works, the button lands on 「暫時無法連線」, and the next login after recovery works without a restart. Pinned by Task 1 `TestNewNoNetwork` and `TestDiscoveryRetried`, and by Task 2 `TestOIDCStartUnavailable`.
5. **Entra groups overage / a string vs array admin claim.** Overage gives staff and is audited, never admin; a string claim and an array claim both match. Pinned by Task 1 `TestIdentityClaims` and Task 2 `TestOIDCLoginOverageAudited`.

**Interfaces:**
- Produces:
  - `config.OIDCConfig{Issuer, ClientID, ClientSecret, Scopes, AdminClaim, AdminValue, ButtonText, CAFile string}` as `Config.OIDC`.
    - Validation, only when `Issuer != ""`: the issuer must parse with scheme `https` and a host; the client id and secret are required; the CA must load.
  - `type Flow struct{ State, Nonce, Verifier string }`
  - `type Identity struct{ ExternalID, Email, Name string; Admin, GroupsOverage bool }`
  - `var ErrUnavailable, ErrInvalid, ErrNoEmail = errors.New(...)`
  - `func New(cfg config.OIDCConfig, redirectURL string) (*Provider, error)`: no network.
  - `(*Provider).Start(ctx) (authURL string, f Flow, err error)`
    - Discovers if needed, then makes a fresh Flow.
    - The URL carries `state`, `nonce` and `code_challenge` (S256, via `oauth2.S256ChallengeOption`).
  - `(*Provider).Exchange(ctx, code string, f Flow) (Identity, error)`
    - Exchanges the code with `oauth2.VerifierOption(f.Verifier)`.
    - Verifies the ID token with `provider.Verifier(&oidc.Config{ClientID})`.
    - Checks `idToken.Nonce == f.Nonce`, then maps the claims.
