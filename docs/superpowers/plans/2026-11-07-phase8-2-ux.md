# Phase 8.2: User-Visible Fixes, Accessibility, i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the parked problems a person sees on screen (spec §3.3) and finish the i18n sweep before v1.0.

**Architecture:** Mostly web (React + TS) changes with small Go handler changes where the server returns the wrong thing. One new shared hook (`useModal`) and one shared error-key helper; everything else edits existing files.

**Tech Stack:** Go 1.27, React 19 + TS, react-i18next, vitest + @testing-library/react + jsdom.

**Spec:** `docs/superpowers/specs/2026-11-07-phase8-release-design.md` (§3.1, §3.3). Parent: `docs/superpowers/specs/2026-10-24-secure-exchange-design.md`.

- Go: coverage ≥ 90% in CI (aim ≥ 91.5% locally); golangci-lint v2 incl. ST1005 and goimports `-local github.com/tntrock/secure-exchange`. DB tests: `SX_TEST_DATABASE_URL='postgres://sx:sx@localhost:55432/sx?sslmode=disable'`; no `-race` locally.
- Never call pool-based `rules.Get` while holding a transaction.
- Each item first confirms the problem still exists; if fixed already, add the pinning test only and say so.

## Review Focus

1. A recipient clicking Download on a file the server will refuse (unmarkable, scan pending, view-only) must see a translated message on the same page, never a raw JSON page — pinned in Task 1.
2. Ctrl/⌘-click and middle-click on Download must open the browser's own new tab — pinned in Task 1.
3. Keyboard-only user: opening ShareDialog or the Viewer puts focus inside, Tab cannot leave it, Esc closes it, focus returns to the button that opened it — pinned in Task 2.
4. After a session expiry on a deep link (e.g. `/vendor/shares/<id>`), signing in returns the user to that page, but a crafted `from` like `//evil.example` is ignored — pinned in Task 3.
5. An upload request whose own extension list and the site list share nothing must tell the uploader nothing is accepted, not "any file type" — pinned in Task 5.

## Rulings

- i18n sweep found web/src clean (only the language names in `LangSwitch.tsx`, intentional). Mail bodies and the tighten digest stay bilingual by design (spec §3.3). The only change is Task 6's plain-text `http.Error` bodies in `internal/webui/webui.go`, which stay English (developer-facing) — no change; recorded here so reviewers don't flag it.

**Interfaces:**
- Produces: `export async function headFile(url: string): Promise<void>` in `api.ts` — `fetch(url, {method: "HEAD", credentials: "same-origin"})`; throws `ApiError(status, code)` on non-2xx. HEAD has no body, so the code is derived from status: 403 → `"forbidden"`, 409/423 → `"scan_pending"`, 429 → `"rate_limited"`, else `"error"`. Ruling: the server already runs every refusal before its HEAD branch (`recipient_download.go:~96`), so the status is exact; the specific 403 reason is then fetched with one `GET` of the same URL using `fetch` + `res.json()` **only when** status is 403 (the GET returns JSON on refusal and never starts a download on refusal).
- Produces: `export function errKey(e: unknown): string` in `errKey.ts` returning a `recipient.error.*` key; covers at least `domain_blocked`, `ip_denied`, `unmarkable`, `view_only`, `quarantined`, `scan_pending`, `scan_failed`, falling back to `app.error`.

  - Access: `fireEvent.click(link, {ctrlKey: true})` (and `metaKey`, `shiftKey`) → handler does not call `preventDefault` (assert `nav.go` not called and the event's `defaultPrevented` is false).
