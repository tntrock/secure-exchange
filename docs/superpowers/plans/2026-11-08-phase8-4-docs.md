# Phase 8.4 雙語文件 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 中文文件整理到 v1.0 水準，並補齊英文版管理員手冊與使用者手冊，中英章節結構一致，設定變數與程式一致。

**Architecture:** 純文件 PR，外加一個 Go 測試把「程式讀取的 `SX_*` 變數」與 `.env.example`、中英管理員手冊綁在一起，日後新增變數忘了寫文件會讓 CI 失敗。

**Tech Stack:** Markdown、Go 測試（`internal/config`）。

**Spec:** `docs/superpowers/specs/2026-11-07-phase8-release-design.md` §5

## Global Constraints

- 中文維持原檔名：`README.md`、`docs/admin-manual.md`、`docs/user-manual.md`。
- 英文版：`README.en.md`（已存在）、`docs/admin-manual.en.md`、`docs/user-manual.en.md`。
- 每份文件第一行標題下方互相連結：中文檔放 `[English](<對應 .en.md>)`，英文檔放 `[繁體中文](<對應 .md>)`。
- 中英兩版章節結構相同：同樣的標題層級、同樣的章節數、同樣的順序。
- 指令、變數名稱、預設值必須與程式（`internal/config/config.go`、`cmd/secure-exchange/main.go`）和 `.env.example` 一致。
- 英文措辭以清楚正確為準，不必逐句直譯。
- 介面文字（按鈕、頁面名）英文版要用 `web/src/i18n/en.json` 裡的實際英文字串，中文版用 `zh-TW.json` 的字串。
- 不改任何產品程式碼；唯一新增的程式是 Task 1 的測試。

## Rulings（控制者決定）

- **快速部署改成拉映像** 移到 8.5：映像在 8.5 才存在，8.4 先改的話 main 上的說明會指向不存在的映像。8.5 會同時改 compose 與 README／手冊的部署與升級段落。
- **「目前要用 SQL」段落**：盤點後剩下的 SQL（`email_conflict` 處理、掃描狀態統計、寄信佇列查詢）都沒有對應介面，保留。只移除已有介面可做的段落；若盤點時發現某段已有介面，改寫成介面操作。
- **設定總覽** 沿用管理員手冊既有的「4. 設定參考」，補齊缺漏，不另開章節；README 只連結過去。
- **升級** 沿用既有「15. 升級」，補上「版本說明」與 `.env.example` 比對的步驟；拉映像版本的寫法留給 8.5。

## Review Focus

- 程式有讀但文件沒寫的變數（例如清理排程、`GOMEMLIMIT`、`SX_LISTEN`）→ Task 1 的測試會抓到。
- `SX_BASE_URL` 在 compose 中由 `SX_DOMAIN` 組成、不帶 `SX_HTTPS_PORT`；非 443 埠需手動設定 → 寫進設定參考與快速部署。
- 英文版遺漏章節或錨點連結失效（中文錨點如 `#7-強制規則` 在英文版要換成英文錨點）。
- 英文版介面字串與實際 en.json 不符（例如按鈕名稱）。
- README 功能清單仍寫「第一至六階段」或遺漏第七、八階段功能（LDAP、OIDC、全站瀏覽、強制規則、溯源、清理）。
